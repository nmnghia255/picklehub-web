# Đặc tả Kỹ thuật: Thao tác & Luồng Vận hành Trận đấu (Match Operations)

Tài liệu này đặc tả chi tiết các thao tác vận hành, luồng xử lý và giao thức truyền tải dữ liệu liên quan đến trận đấu giữa **Tournament Service** (`tournament-service`) và **Match Service** (`match-service`).

---

## 1. Kiến trúc & Các Thực thể Vận hành

Hệ thống quản lý và vận hành trận đấu được chia làm hai phân hệ chính phối hợp qua REST API và WebSockets Gateway:
*   **Tournament Service**: Quản lý lịch thi đấu địa phương (`Fixtures`), sơ đồ bảng đấu, nhánh loại trực tiếp (Knockout) và phân bổ trọng tài.
*   **Match Service**: Chịu trách nhiệm khởi tạo trận đấu thực tế (`Match`), ghi nhận điểm số thời gian thực (Live Score) và điều hành phòng WebSocket dành cho trọng tài/khách hàng.

---

## 2. Luồng Công việc Toàn diện (End-to-End Match Flow)

### Bước 1: Phát hành trận đấu (Dispatch Fixtures)
Sau khi xếp lịch thi đấu tự động hoặc thủ công lên sân đấu:
1. BTC gửi yêu cầu phát hành trận đấu sang Match Service qua API `POST /api/tournaments/:tournamentId/fixtures/dispatch`.
2. Hệ thống kiểm tra các trận đấu đủ điều kiện:
    *   Trạng thái hiện tại: `scheduled` hoặc `ready`.
    *   Đã gán sân thi đấu và slot đặt sân được xác nhận (`CONFIRMED`).
    *   Đội hình đã được chốt và hợp lệ (2 VĐV cho đánh đôi, 1 VĐV cho đánh đơn).
3. Match Service tiếp nhận và sinh mã **UUID trận đấu thực tế**, đồng thời lưu thông tin trọng tài phụ trách (`refereeId`).
4. Tournament Service cập nhật mã UUID này vào trường `externalMatchId` và đổi trạng thái lịch đấu sang `ready` (sẵn sàng thi đấu).

### Bước 2: Ghi điểm trực tuyến (Live Score qua WebSockets)
Khi trận đấu bắt đầu diễn ra thực tế:
1. Trọng tài sử dụng thiết bị kết nối vào Websocket Gateway `ws://match-service/matches` kèm theo JWT token để xác thực quyền điều hành.
2. Trọng tài gửi sự kiện `join-match` kèm `{ matchId: string }` để đăng ký lắng nghe và điều khiển phòng đấu.
3. Khi có điểm số phát sinh, trọng tài gửi sự kiện `score-point`:
    *   **Luật thi đấu (Best-of-3)**: Một set đấu kết thúc khi một đội đạt 11 điểm trước (và phải cách biệt tối thiểu 2 điểm). Trận đấu kết thúc khi một đội thắng trước 2 set đấu.
4. Mỗi điểm số thay đổi sẽ được Server phát trực tiếp đến tất cả các thiết bị đang kết nối trong phòng qua sự kiện `match-event` (với dữ liệu `"event": "point-scored"`).

### Bước 3: Hoàn tác điểm số (Undo Point)
Trường hợp trọng tài ghi nhận điểm nhầm lẫn:
1. Trọng tài gửi sự kiện `undo-point` lên WebSocket Gateway.
2. Hệ thống sẽ **xóa điểm số ghi nhận gần nhất** trong bảng lịch sử ghi điểm (`MatchScoreHistory`) và tính toán lại kết quả set hiện tại.
3. Server broadcast sự kiện `match-event` (với dữ liệu `"event": "point-undone"`) để thiết bị người xem cập nhật lại bảng điểm.
4. **Giới hạn**: Chỉ cho phép hoàn tác **1 điểm gần nhất**. Nút Undo trên giao diện sẽ bị vô hiệu hóa nếu set đấu hiện tại chưa có điểm số nào được ghi.

### Bước 4: Tự động đồng bộ và Tiến cấp (Auto Sync & Advancement)
Khi trận đấu đi đến kết quả chung cuộc:
1. Tại set đấu quyết định, ngay khi một đội đạt đủ điều kiện thắng set thứ 2, Match Service đổi trạng thái trận đấu thành `CONFIRMED`.
2. Match Service thực hiện gọi HTTP Callback trực tiếp đến Tournament Service qua API `/api/tournaments/internal/fixtures/sync-by-uuid`.
3. Tournament Service đồng bộ kết quả tỷ số chung cuộc, cập nhật trạng thái lịch đấu địa phương thành `completed` và tiến hành:
    *   **Vòng bảng**: Tự động tính toán lại bảng xếp hạng (Standings) của bảng đấu đó.
    *   **Vòng loại trực tiếp (Knockout)**: Tự động đưa tên đội thắng vào slot trận đấu tiếp theo ở vòng sau (dựa trên liên kết `nextMatchId`).

## 3. Danh sách các API REST liên quan

Các API được bảo vệ bởi lớp kiểm tra quyền Ban Tổ Chức (`TournamentOrganizerGuard`):

| Phương thức | Đường dẫn API | Mô tả |
| :--- | :--- | :--- |
| `POST` | `/api/tournaments/:tournamentId/fixtures/dispatch` | Phát hành các trận đấu đủ điều kiện sang Match Service để mở cổng ghi điểm |
| `POST` | `/api/tournaments/:tournamentId/fixtures/:fixtureId/result` | Nhập/ghi đè kết quả trận đấu thủ công trong trường hợp khẩn cấp |
| `POST` | `/api/tournaments/:tournamentId/fixtures/sync` | Kéo dữ liệu và đồng bộ thủ công tất cả kết quả trận đấu đã xác nhận từ Match Service |
| `POST` | `/api/tournaments/:tournamentId/matches/:matchId/assign` | Gán trọng tài điều hành và cấp quyền ghi điểm qua WebSocket |
| `POST` | `/api/tournaments/:tournamentId/referees/bulk-assign` | Phân bổ hàng loạt trọng tài cho nhiều trận đấu cùng lúc |
| `DELETE` | `/api/tournaments/:tournamentId/matches/:matchId/unassign` | Hủy gán trọng tài và thu hồi quyền ghi điểm của trận đấu |

## 4. Giao thức WebSocket Gateway

*   **Giao thức kết nối**: **Socket.IO** (Sử dụng thư viện Socket.IO Client).
*   **Đường dẫn kết nối (Namespace)**: Kết nối đến Namespace `/matches` trên hệ thống API Gateway (Ví dụ: `https://api.picklehub.vn/matches` ở môi trường production hoặc `ws://localhost:8009/matches` ở môi trường phát triển).

### Sự kiện Client gửi lên (Client Emit)

#### 1. Vào phòng đấu (`join-match`)
Đăng ký nhận cập nhật điểm số thời gian thực.
```json
// Event: 'join-match'
{
  "matchId": "string (UUID)"
}
```

#### 2. Cộng điểm (`score-point`)
Ghi nhận điểm số mới (Yêu cầu xác thực quyền trọng tài được gán).
```json
// Event: 'score-point'
{
  "matchId": "string (UUID)",
  "setId": "number (1, 2 hoặc 3)",
  "scoringTeam": "TEAM_A | TEAM_B"
}
```

#### 3. Hoàn tác điểm (`undo-point`)
Hủy bỏ điểm số vừa ghi gần nhất (Yêu cầu xác thực quyền trọng tài được gán).
```json
// Event: 'undo-point'
{
  "matchId": "string (UUID)"
}
```

#### 4. Rời phòng đấu (`leave-match`)
Ngừng nhận cập nhật từ phòng đấu.
```json
// Event: 'leave-match'
{
  "matchId": "string (UUID)"
}
```

### Sự kiện Server phát đi (Server Broadcast)

#### Broadcast cập nhật trạng thái (`match-event`)
Được phát đi cho toàn bộ thiết bị đang ở trong phòng trận đấu sau mỗi thao tác ghi điểm/hoàn tác.
```json
// Event: 'match-event'
{
  "event": "point-scored | point-undone | match-completed",
  "matchId": "string (UUID)",
  "score": {
    "scoreA": "number (Điểm set hiện tại của đội A)",
    "scoreB": "number (Điểm set hiện tại của đội B)",
    "sets": "array (Mảng lưu tỷ số các set, ví dụ: [[11, 8], [9, 11], [4, 2]])",
    "currentSetId": "number (Set đấu hiện tại)",
    "server": "TEAM_A | TEAM_B | null"
  },
  "lastAction": {
    "type": "point | undo",
    "team": "TEAM_A | TEAM_B (Chỉ có khi type là point)",
    "timestamp": "string (ISO 8601 UTC)"
  },
  "status": "LIVE | CONFIRMED"
}
```

## 5. Ràng buộc Tích hợp Frontend & Trải nghiệm mất mạng (Offline UX)

### Khôi phục trạng thái (State Recovery)
Khi thiết bị trọng tài bị mất kết nối mạng và kết nối lại thành công:
1. Client phát lại sự kiện `join-match` để tham gia lại socket room.
2. Vì server không tự động gửi lại điểm số hiện tại khi join, **Frontend bắt buộc phải tự gọi API REST** `GET /api/matches/:id` để lấy điểm số mới nhất làm nguồn dữ liệu chuẩn (Single Source of Truth) và đồng bộ lại giao diện bảng điểm.

### Đóng băng màn hình (Screen Freeze)
Để tránh tình trạng trọng tài bấm ghi điểm khi thiết bị ngoại tuyến (không thể gửi lên server và sẽ bị mất điểm do hệ thống không có hàng đợi offline queue):
1. Khi phát hiện sự kiện Socket.IO bị `disconnect`, Frontend **bắt buộc phải vô hiệu hóa (freeze) toàn bộ màn hình ghi điểm** và hiển thị banner `"⚠️ Mất kết nối..."`.
2. Khi kết nối lại và trong quá trình gọi REST API để đồng bộ, hiển thị trạng thái `"🔄 Đang đồng bộ..."` và tiếp tục khóa nút bấm.
3. Chỉ mở khóa màn hình điều khiển khi REST API đồng bộ điểm số trả về kết quả thành công.
